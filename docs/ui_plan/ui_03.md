# UI-03 — Monaco Editor Integration & Editor System

## 1. Objective

Xây dựng hệ thống Editor cho Java SQL IDE bằng cách tích hợp Monaco Editor vào JavaFX.

Mục tiêu:

* Tích hợp Monaco Editor vào JavaFX WebView.
* Xây dựng hệ thống quản lý nhiều Editor Tabs.
* Quản lý nội dung và trạng thái tài liệu.
* Hỗ trợ SQL, XML, JSON và Text.
* Xây dựng giao diện Editor hiện đại.
* Chuẩn bị kiến trúc để tích hợp SQL Intelligence trong các phase sau.

Tham khảo cách tổ chức Editor của VS Code, DataGrip và LLTool.

Không yêu cầu triển khai SQL Intelligence hoặc Backend trong phase này.

## 6. Multiple Editor Models

Đây là phần cần thiết kế cẩn thận.

Mỗi tài liệu tương ứng với một Monaco TextModel riêng.

Ví dụ:

```text
EditorModelManager
│
├── Document 001
│   └── Monaco TextModel
│
├── Document 002
│   └── Monaco TextModel
│
└── Document 003
    └── Monaco TextModel
```

Yêu cầu:

* Tạo Model khi tạo tài liệu.
* Chuyển Model khi đổi tab.
* Không tạo lại Model khi chuyển tab.
* Giữ nguyên nội dung.
* Giữ nguyên Undo / Redo history trong vòng đời Model.
* Giữ nguyên Cursor Position.
* Giữ nguyên Selection.
* Giữ nguyên Scroll Position.
* Dispose Model khi tài liệu thực sự được đóng.

Không tạo một Monaco Editor instance cho mỗi tab.

Sử dụng một Editor instance chính và chuyển đổi Model.

## 10. JavaScript ↔ Java Bridge

### 10.1 Architecture

```text
JavaFX
   │
   │ Command
   ▼
JavaScript Bridge
   │
   ▼
Monaco Manager
   │
   │ Event
   ▼
JavaScript Bridge
   │
   ▼
JavaFX
```

### 10.2 Java → Monaco

Các lệnh tối thiểu:

* createDocument.
* openDocument.
* switchDocument.
* closeDocument.
* setValue.
* getValue.
* setLanguage.
* executeCommand.
* updateEditorOptions.
* setTheme.

### 10.3 Monaco → Java

Các sự kiện:

* editorReady.
* contentChanged.
* cursorPositionChanged.
* selectionChanged.
* activeModelChanged.
* languageChanged.
* editorError.

### 10.4 Message Protocol

Thiết kế message có cấu trúc JSON:

```json
{
  "id": "command-001",
  "type": "command",
  "action": "switchDocument",
  "payload": {
    "documentId": "doc-001"
  }
}
```

Event:

```json
{
  "id": "event-001",
  "type": "event",
  "action": "contentChanged",
  "payload": {
    "documentId": "doc-001",
    "dirty": true
  }
}
```

Yêu cầu:

* Có command ID.
* Có action.
* Có payload.
* Có cơ chế xử lý lỗi.
* Không truyền dữ liệu tùy tiện qua các hàm JavaScript rời rạc.
* Không gọi JavaFX UI trực tiếp từ thread JavaScript.
* Tuân thủ JavaFX Application Thread.

Không cần xây dựng hệ thống RPC phức tạp.

## 15. Performance Requirements

* Chỉ sử dụng một Monaco Editor instance chính.
* Mỗi tài liệu có Model riêng.
* Không reload WebView khi chuyển tab.
* Không gửi toàn bộ nội dung tài liệu về Java sau mỗi lần gõ.
* Không đồng bộ nội dung theo kiểu polling liên tục.
* Sử dụng event-driven communication.
* Debounce các sự kiện không cần xử lý tức thời.
* Không để thao tác UI bị block bởi việc đồng bộ dữ liệu lớn.
